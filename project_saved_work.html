03 Before and after

What the redesign changed

Before
  • 14 file types in one flat, undifferentiated list
  • No project context or filter
  • No search within sections
  • No metadata without opening the file
  • Actions hidden or duplicated across types
  • No sharing across contracts in the same org
  • Users keeping external Excel to manage their work
  • 7 sections with under 2% usage, effectively abandoned
After
  • Three zones: Project Workspace, Repository, Folders
  • Navigation filtered by the active project
  • Search built into every section header
  • Item detail panel always visible on the right
  • Actions consolidated and surfaced per file type
  • Shared Folders visible across contracts in same org
  • All work manageable without leaving the product
  • Inbox removed, sections restructured by actual workflow
04 Roadmap

Two directions we considered

Option A, recommended
Ship this redesign first

Immediate improvement. Generates real usage data to scope the larger Project Management build.

  • Ship Saved Work redesign
  • Observe adoption patterns
  • Scope Project Management from real data
  • Migrate gradually, lower risk
Option B
Skip to full Project Management

Given low usage, skip the interim fix and invest directly in the full rebuild.

  • Skip this redesign
  • Define full PM scope
  • Build and ship new core flow
  • Full migration required

Decision pending — depends on migration feasibility and engineering capacity.

05 Reflection

What I learned

What worked
  • Auditing all 14 file types and their actions first, so I had full understanding before touching the solution.
  • The three-zone rail came from how researchers actually describe their work: by project, not file type.
  • Pendo data gave the team an objective shared starting point that cut through assumptions.
  • Two concrete roadmap options made the strategic conversation possible.
Still open
  • Roadmap decision pending, which affects whether this ships or is absorbed into a larger scope.
  • Cross-contract sharing needs a legal and permissions review before full spec.
  • Project Details is new and needs usability testing before development.
  • Large-portfolio users (100+ items) not yet tested.
